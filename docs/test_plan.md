## 1. Цели и задачи тестирования

**Цель** — проверить, что функции библиотеки Geometric Lib вычисляют площадь и периметр
геометрических фигур в соответствии с описанием из [справочника функций](funct.md).

**Задачи:**

- определить наборы входных данных для каждой функции и вручную рассчитать ожидаемые ответы;
- написать автоматические unit-тесты на основе модуля `unittest` для всех четырёх фигур;
- запустить тесты и зафиксировать фактические результаты;
- проанализировать проваленные тесты и сделать выводы о качестве библиотеки.

Тесты пишутся как для «чёрного ящика»: ожидаемые значения определяются только по формулам
и примерам из документации, а не по исходному коду.

## 2. Описание тестируемого продукта

Geometric Lib — библиотека на Python для вычисления площади и периметра геометрических фигур.
Каждая фигура реализована в отдельном модуле:

| Модуль | Функции | Формулы |
|---|---|---|
| `circle.py` | `area(r)`, `perimeter(r)` | S = π·r², P = 2·π·r |
| `square.py` | `area(a)`, `perimeter(a)` | S = a², P = 4·a |
| `rectangle.py` | `area(a, b)`, `perimeter(a, b)` | S = a·b, P = 2·(a + b) |
| `triangle.py` | `area(a, h)`, `perimeter(a, b, c)` | S = a·h / 2, P = a + b + c |

Подробное описание функций — в [справочнике](funct.md).

## 3. Область тестирования

**В области тестирования:** все 8 функций четырёх модулей (`circle.py`, `square.py`,
`rectangle.py`, `triangle.py`).

**Вне области тестирования:** производительность, безопасность, пользовательский интерфейс
(у библиотеки его нет), а также изменение логики работы фигур.

## 4. Стратегия тестирования

- **Вид тестирования:** функциональное, модульное (unit) тестирование методом чёрного ящика.
- **Инструмент:** стандартный модуль Python `unittest`.
- **Организация:** для каждого модуля создан отдельный файл в каталоге `tests/`
  (`test_circle.py`, `test_square.py`, `test_rectangle.py`, `test_triangle.py`);
  для каждой функции — свой класс-наследник `unittest.TestCase`.
- **Техники подбора данных:**
  - типичные значения (в том числе примеры из справочника);
  - граничные значения (ноль, единица);
  - дробные числа;
  - большие значения;
  - свойства функций (например, площадь прямоугольника не зависит от порядка сторон);
  - недопустимые данные (отрицательные значения; стороны, не образующие треугольник) —
    ожидаем исключение `ValueError`.
- **Ручной расчёт:** ожидаемые значения получены вручную по формулам, затем зафиксированы в тестах.
  Для вещественных результатов используется `assertAlmostEqual`.

Запуск всех тестов (из корня репозитория):

```
python3 -m unittest -v
```

## 5. Критерии приемки

Тестирование считается успешно завершённым, если:

1. тесты написаны для всех 8 функций всех 4 фигур;
2. все тесты корректных данных (типичные, граничные, дробные, большие значения) проходят;
3. все проваленные тесты проанализированы, а причина каждого описана в разделе 8;
4. логика работы фигур не изменена;
5. исходный код тестов размещён в репозитории на GitHub.

## 8. Выводы из результатов тестирования

1. **Корректные данные.** Все 43 теста пройдены: площади и периметры всех четырёх фигур
   вычисляются в соответствии с формулами и примерами из справочника, в том числе для нуля,
   дробных и больших значений.
2. **Недопустимые данные.** Все 9 проваленных тестов относятся к одной проблеме: функции
   не проверяют входные значения. Для отрицательного радиуса или стороны они возвращают число
   (например, `square.area(-3)` даёт 9), а для сторон 1, 1, 10 возвращают периметр несуществующего
   треугольника. Поведение для таких данных в справочнике не описано, поэтому это замечание
   к полноте библиотеки, а не нарушение описанных формул.
3. **Дефект в `triangle.py`.** Синтаксическая ошибка в docstring (лабораторная работа 2) делала
   модуль непригодным к импорту. Дефект исправлен, после этого все тесты треугольника запускаются.
   Это показывает ценность автоматических тестов: ошибка найдена при первом же запуске.
4. **Критерии приемки.** Критерии 1, 2, 3 и 5 выполнены. Критерий 4 выполнен с оговоркой:
   логика фигур не менялась, исправлена только синтаксическая ошибка в `triangle.py`.
5. **Рекомендации.** Добавить в функции проверку входных данных (вызывать `ValueError`
   для отрицательных значений и для сторон, нарушающих неравенство треугольника) и описать
   это поведение в справочнике. После этого 9 проваленных тестов должны начать проходить.
